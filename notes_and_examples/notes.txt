        Yes, it’s possible for the alephRBC code to fetch the list of nodes dynamically from the API.         Is listen_address in the TOML required?
        The listen address can be defined directly in the Rust code with "/ip4/0.0.0.0/tcp/30333". Defining it within the TOML allows for easier reconfiguration if the address or port ever needs to be changed without recompiling the code.

        Should batch_size and transaction_size be defined in TOML or Rust?
        Including these in the TOML provides flexibility to adjust transaction and batch size settings dynamically without modifying the Rust code. This approach is beneficial if you anticipate frequently adjusting these parameters.

        Is the transaction_metrics_log path required in TOML?
        Defining the log path in TOML allows easy reconfiguration if the log file path ever needs to change. However, if the path is fixed and unlikely to change, it could be hardcoded in Rust.

        Should id and total_nodes be in the TOML?
        Since total_nodes can be derived from the bootnode list fetched from the API, it’s not strictly necessary in the TOML. Likewise, id could be set dynamically at runtime if each node can determine its ID based on some unique property.
